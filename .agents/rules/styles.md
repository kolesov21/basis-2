# Стили: Tailwind CSS

## Основной подход

- Используем Tailwind CSS 4 через `@tailwindcss/vite`.
- Стили элемента задаём utility-классами в шаблоне Vue. Адаптивность и состояния —
  через варианты Tailwind (`md:`, `hover:`, `focus-visible:`, `disabled:`).
- Собственный CSS допустим, когда он понятнее utility-классов: например, для сложных
  анимаций, Vue-переходов или интеграции сторонних компонентов.
- Повторяющиеся элементы интерфейса выносим в Vue-компоненты. Не создаём компонент
  только ради сокращения строки классов и не заменяем утилиты повсеместным `@apply`.
  `@apply` — исключение с конкретной причиной, а не основной способ организации стилей.

## Где хранить стили

- `src/styles/main.css` — единая глобальная точка входа, импортируемая один раз в `src/main.ts`.
  В ней находятся импорт Tailwind, общие токены и необходимые глобальные правила.
- Общие стили HTML-элементов добавляем в `@layer base`, чтобы utility-классы могли их переопределять.
  Импорт Tailwind уже включает Preflight; дополнительный reset не подключаем без необходимости.
- Локальные исключения пишем в `<style scoped>` соответствующего Vue-компонента.
  Для классов собственного CSS используем понятные имена в kebab-case.
- `:deep()` используем только для обоснованной настройки вложенной разметки стороннего
  компонента, ограничивая селектор локальным контейнером.
- Не повышаем специфичность селекторов и не применяем `!important` для обычной стилизации.
  Вынужденное переопределение сторонних стилей сопровождаем комментарием с причиной.

## Токены и значения

- Сначала используем стандартную шкалу Tailwind: отступы, размеры, типографику и цвета.
- Повторяющиеся значения из макета, которых нет в подходящей стандартной шкале,
  выносим в `@theme` в `src/styles/main.css`. Используем соответствующие пространства имён
  (`--color-*`, `--spacing-*`, `--text-*`, `--font-*` и другие).
- Палитру и шрифты выбираем под конкретное задание. Не создаём токены заранее без потребности.
- Произвольные значения вроде `w-[350px]` допустимы для разовых требований макета.
  Если значение становится общим дизайнерским решением, используем токен.
- В собственном CSS обращаемся к общим токенам через `var(...)`, не копируем их значения.
  Обычные CSS-переменные, которым не нужны utility-классы, объявляем в `:root` или локально.

## Классы и динамические значения в Vue

- Для условных классов используем `:class` с объектом, массивом или выбором готовой строки.
  Имена классов должны быть записаны целиком: `active ? 'bg-blue-600' : 'bg-gray-600'`.
- Не собираем имена из частей, например `bg-${color}-600`: Tailwind не обнаружит их при сборке.
  Для вариантов компонента используем отображение значений props на полные строки классов.
- Значения, вычисляемые во время выполнения (например, ширина прогресса), передаём через
  `:style` или CSS-переменные. Статические стили оставляем в классах.
- Не задаём конфликтующие утилиты для одного свойства в одном состоянии и брейкпоинте:
  порядок классов в атрибуте не определяет приоритет CSS. Выбираем нужный вариант явно.

## Форматирование и проверка

- Порядок классов задаёт `prettier-plugin-tailwindcss`, вручную собственный порядок не вводим.
  Плагин настроен на `src/styles/main.css`, чтобы учитывать тему проекта.
- `npm run format` сортирует классы в `class` и поддерживаемых выражениях `:class`;
  `npm run format:check` проверяет форматирование. Произвольные строки в TypeScript
  не считаем автоматически отсортированными.
- При изменении подключения Tailwind проверяем production-сборку: `npm run build`.
  При изменении интерфейса проверяем адаптивность, состояния и видимый фокус с клавиатуры.
  Архитектурные соглашения проверяются на ревью; Prettier контролирует форматирование.
