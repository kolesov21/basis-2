# basis-2 — площадка для тестовых заданий

Проект для выполнения тестовых заданий на собеседованиях.
Стек: **Vue 3** + **TypeScript strict** + **VueUse** + **Tailwind CSS**, сборка Vite, тесты Vitest.

Правила:

- стек — [`.agents/rules/vue-stack.md`](.agents/rules/vue-stack.md)
- стили — [`.agents/rules/styles.md`](.agents/rules/styles.md)
- git — [`.agents/rules/git.md`](.agents/rules/git.md)

Перед началом работы прочитай все три файла правил. `.agents/rules/` — обычные Markdown-файлы,
которые нужно читать явно; они не подключаются автоматически.

Все скилы проекта лежат локально в `.agents/skills/`, правила — в `.agents/rules/`.

Навык перед применением читать из `.agents/skills/<имя>/SKILL.md`.

## Структура проекта

- `src/main.ts` — точка входа Vue, `src/App.vue` — корневой компонент.
- `src/styles/main.css` — подключение Tailwind CSS, общие токены и глобальные стили.
- `src/__tests__/App.spec.ts` — тест корневого компонента; окружение тестов — jsdom.
- `vite.config.ts` — сборка и алиас `@` → `src/`, `vitest.config.ts` — настройки тестов.
- `eslint.config.ts`, `.oxlintrc.json`, `.prettierrc.json` — правила качества кода.
- `.husky/` — проверки имени ветки и сообщений коммитов.
- Пакетный менеджер — npm, требуется Node.js ≥ 24.12.

## Флоу задачи (обязательный порядок)

1. **Grilling** — каждый запрос, который меняет код или файлы, сначала проходит через скил `grilling`.
   Никаких изменений до того, как пользователь подтвердит общее понимание задачи.
   Исключения: вопросы и объяснения без изменений; явная фраза пользователя «без grilling».
2. **Ветка** — от актуального `main` создать ветку задачи по правилам git.
3. **Дизайн** — если ссылки на макеты не даны, UI проектируется по скилу `frontend-design`.
   Если макет есть — следуем макету.
4. **Реализация** — по принципам скила `karpathy-guidelines`: допущения проговариваются явно,
   минимум кода без спекулятивных абстракций, точечные правки, проверяемый критерий готовности.
5. **Проверки** — проходят `npm run type-check`, `npm run lint`, `npm run format:check`, `npm test`.
6. **Ревью** — скил `post-task-review`. Итог каждого шага кратко сообщить пользователю;
   задача не считается готовой без всех трёх шагов:
   1. code review текущего диффа средствами Codex, найденное исправить;
   2. соответствие диффа принципам `karpathy-guidelines`;
   3. финальное полное ревью итогового диффа.
7. **Коммиты** — предложить разбивку и сообщения, закоммитить после подтверждения пользователя.
