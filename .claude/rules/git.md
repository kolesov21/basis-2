# Git: соглашение по веткам и коммитам

## Коммиты — Conventional Commits

```
<type>(<scope>): <описание>

<тело — необязательно: зачем сделано изменение>
```

- **Описание** — на русском, в инфинитиве («добавить», «исправить»), с маленькой буквы, без точки в конце.
- **Заголовок** целиком — не длиннее 72 символов.
- **Scope** — необязателен, латиницей в нижнем регистре: область кода (`cart`, `api`, `form`).
- Один коммит — одно логическое изменение; проект собирается и проходит проверки на каждом коммите.
- Без трейлеров `Co-Authored-By` и пометок об инструментах.

| Тип        | Когда                                                    |
|------------|----------------------------------------------------------|
| `feat`     | новая функциональность для пользователя                  |
| `fix`      | исправление ошибки                                       |
| `refactor` | изменение кода без изменения поведения                   |
| `perf`     | улучшение производительности                             |
| `style`    | форматирование, без изменения логики                     |
| `test`     | тесты                                                    |
| `docs`     | документация, правила, README                            |
| `build`    | сборка и зависимости                                     |
| `ci`       | CI-конфигурация                                          |
| `chore`    | служебное: настройка инструментов, конфиги               |
| `revert`   | откат предыдущего коммита                                |

Примеры:
```
feat(cart): добавить счётчик количества
fix(api): обработать пустой ответ сервера
chore: настроить commitlint и husky
```

## Ветки

- Формат: `<type>/<kebab-описание>` — тип из таблицы выше, описание на английском, 2–5 слов.
  Примеры: `feat/product-list`, `fix/cart-total-rounding`, `chore/project-setup`.
- Regex: `^(feat|fix|refactor|perf|style|test|docs|build|ci|chore|revert)/[a-z0-9]+(-[a-z0-9]+)*$`
- `main` всегда стабилен: прямые коммиты в `main` запрещены, только слияния.
- Слияние в `main` — `git merge --no-ff <ветка>`, чтобы ветка была видна в истории отдельным блоком.

## Кто и когда

- Ветку задачи Claude создаёт сам — сразу после grilling, от актуального `main`.
- После ревью Claude предлагает разбивку на коммиты с сообщениями и коммитит только после подтверждения пользователя.
- Merge в `main` и push — только по явной просьбе пользователя.

## Автоматические проверки (husky)

- `commit-msg` — commitlint (`@commitlint/config-conventional`, заголовок ≤ 72 символов).
- `pre-commit` — имя ветки по regex выше; на `main` разрешён только коммит слияния.
- Хуки не обходить (`--no-verify` запрещён); если хук упал — исправить причину.
